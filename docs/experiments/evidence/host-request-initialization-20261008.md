# Host request initialization (2026-10-08)

The actual `server.mjs` foreground execution boundary encloses the initial startup read, `run_main`, owned wait, `modelStartedResult`, folded `orchestration_complete` and recursive `native_next`. Opening only around one nested call would leave repeated migrations elsewhere in that same authenticated request. The Host now wraps that complete boundary in an async-local request lifetime; it grants no execution authority.

`WorkflowService` retains an initialized Store/Runtime/Executor/coordinator only in that active request, keyed by the exact service object. Internal startup reads, waits and the fixed execution transitions can reuse it. Every transition loads and validates current user configuration and compares the complete config, environment, validation capability data and relevant manager/broker function identities with the original initialization. Changed state reopens; state changing during initialization rejects with `WORKFLOW_REQUEST_INITIALIZATION_CHANGED`. Concurrent same-service callers share only the pending initialization, never execution or authority work. The admission rechecks the exact pending entry after the async config read, preventing duplicate initialization and deleting only its owned failed entry.

Reuse repeats original Store/Runtime directory initialization and link checks. Original selected-pack/Run reads, resources, controller authority, active attempt, admission, leases, pins, dispatch receipts, Main checker, scope audit and cancellation remain in their existing paths. Startup's first read uses the original full opening and Role profiles. An execution-only initialization cannot satisfy a subsequent full-read requirement. Role operations and direct `open()` always initialize and fully validate. Other public operations keep their original behavior. Request settlement marks its context inactive and clears retained entries before observation reporting; late inherited work and requests/services outside that lifetime initialize independently. A request ending during a pending config read cannot publish a retained entry afterward. Initialization and service-transition failures remain visible and discard the affected retained initialization.

The existing bounded foreground report retains `op` for actual opening and migration spans, and adds `ir` for reuse with repeated directory checks. It still checks its original 1000-character audit envelope and failure semantics. No new audit channel, timing log in ordinary libraries, timer, global cache, migration bypass, automatic retry or permission change is introduced.

R2 corrects an introduced runtime-shape regression. R1 applied strict `canonicalJSON` directly to the default Node `process.env` Host object and optional broker/context metadata. Its neutral plain-env tests passed but actual default-env startup failed with `INVALID_JSON` before any Run. The defect belongs to the Host fingerprint, not the supplied startup object or model serialization. R1's source snapshots, qualification and failed samples remain preserved separately.

Strict canonicalization now applies only to already validated configuration. The runtime signature snapshots actual ENV data descriptors into an owned plain object with unchanged keys/values, then explicitly represents own enumerable runtime data, undefined versus omission, sparse arrays, cycles and primitive types. Callable, symbol, prototype and opaque object identities remain separate references. Broker projection inspects only identity, attestation, execute and cancel descriptors, including inherited declarations, without evaluating getters. Missing optional fields and unused null registrations retain original meaning; original selected-tool contract/attestation checks still reject invalid bindings with their original errors. Nonplain contexts preserve their structural data and opaque identity. No raw ENV value or authority-bearing metadata enters diagnostics.

Comparison is bounded to 100,000 visited entries, depth 128 and 8 Mi UTF-16 characters across string keys/values. Exhaustion marks the whole signature non-reusable; no partial signature authorizes reuse and no new execution-limit error strengthens original acceptance. Dynamic accessors and proxy state also decline reuse without invoking unrelated getters/traps. The original fresh opening then decides behavior and exposes its original errors. Existing-channel `ib` and `ia` phases identify those intentional budget/accessor boundaries; inclusive opening spans still overlap. These are optimization eligibility limits, not Workflow schema limits. Observable opaque identity does not imply inspecting hidden closure/internal object state, which continues through original live capability methods and selected-tool checks.

Qualification uses credential-free local neutral fixtures through the actual public typed `workflow_start_prepared` boundary. The initial red fixture completed the original checker and final handoff but opened six times; its green counterpart opens once, with one provider migration, one Host-tool migration, one full Role phase and five reuse phases. This is a fixture-specific call count. Installed observations of seven opens belong to separate retained external evidence. A later observation reported an inclusive opening total of 966.421 ms; the historical approximately four-second total is not a guaranteed saving. Business wall time, cost and quality require separate measurement.

The added tests qualify concurrent and later requests, independent services, same-service initialization admission, configuration revocation and provider/environment/capability changes, malformed config and failed open recovery, direct/Role opening, stale controller rejection, cancellation, original checker rejection, scope failure and async work after settlement. Two additional tests cover basis changes during opening and request settlement during a pending config read. Existing typed-startup, authority, Role, cancellation, observer and MCP tests qualify preserved behavior. The fixed observer allowlist test was updated for the explicit `ir` phase. The new file is registered in the explicit manifest; its exact declared/discovered set is checked separately without running the full manifest.

The original public-startup red, concurrent-initialization red and initial observer-allowlist failure remain in external evidence. The work changes isolated source only, keeps version 1.2 and does not install, publish, start a real model/business Run or alter original failed experiments. Windows fixture checks do not prove other-platform behavior, platform error32 repair or business performance.

R2 qualification adds actual public typed startup with omitted constructor/server `env` options, so both use genuine `process.env` and the ordinary bundled Host registry/managers. Neutral lifecycle injection prevents real model work. It also qualifies absent broker identity/attestation, unused null brokers, optional undefined attestation fields, nonplain/undefined contexts, cyclic metadata, meaningful in-place mutations, function/symbol/opaque identity changes, oversized/deep contexts and untouched irrelevant accessors/proxies. Invalid selected brokers are compared against original direct-opening error behavior. R2 runs the affected request, observer and MCP suites; it does not repeat the complete test manifest or business trials. R1 immutable evidence and R2 before/red/green/final inventories remain distinct.

R3 closes the remaining capture-front gap: R2 inspected nested descriptors safely but first evaluated outer capability fields and used `Object.entries` on registry values. Post-construction mutation could therefore invoke an unused registry getter/proxy trap or add an outer context getter call merely for fingerprinting. Capture now checks service fields and outer capability descriptors/proxies before retrieving values, guards the registry container before enumeration, and retrieves only own data-entry descriptor values. Any dynamic front boundary declines reuse through the existing `ia` phase, leaving the original opening and selected binding validation to perform their own reads and expose their original errors. Tests cover throwing/counting unused registry entries, container proxies, outer context/registry getters and a capabilities-container proxy; scoped fresh reads retain exactly original callback counts. The targeted request and observer suites retain all ordinary R2 behavior. R2 frozen source/evidence remains immutable; R3 has its own before/red/green/final inventory.
