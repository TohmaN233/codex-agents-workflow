# Explicit native tool context profile — 2026-10-09

The r12 batch's fresh native children each began with roughly 31,600 input tokens. Their shared environment included Apps, Plugins and automatic Skill catalogs unrelated to the supplied renderer. Context isolation alone does not remove that static prefix or later model responses.

`caw_native_builtins` is an executor context profile, separate from a Workbench Role. Its standalone TOML disables `features.apps`, `features.plugins` and `skills.include_instructions`. It leaves built-in shell/web tools, permissions and the explicitly selected model/reasoning effort unchanged. Direct globally configured MCP servers remain available. Select it only for a node whose supplied materials and built-in tools cover its dependencies. Other Providers and routes retain their existing context.

The Host passes the registered profile name to Cooperative recorded-child spawning and rejects upstream/full-history inheritance for this profile. Strict, managed native and persistent task executors reject it before dispatch because those adapters cannot apply a native agent profile. It verifies the small installed template and ownership receipt at the binding boundary; it does not scan the source package on each response. Registration uses the normal plugin installer and a namespaced personal agent file because plugin manifests currently have no supported agent-file component. No global model, feature or skill configuration is changed.

The installer rejects an unowned collision or edited owned bytes. Updates use atomic file replacement with a pending receipt so an interrupted registration is visible. `scripts/uninstall-local.mjs` performs the normal plugin removal followed by exact owned-profile cleanup. **Stock external plugin uninstall leaves the personal profile behind.** Its cleanup behavior is not under the plugin's control.

Pinned upstream source establishes the feature-override and discovery paths, but does not prove the installed desktop executable behaves identically. Qualification must separate supported configuration loading, actual native tool/catalog exposure and measured business performance. A profile discovery result alone is insufficient evidence for a token or speed claim. Keep the unchanged Skill sample and whole initiating-Main-plus-children accounting when measuring this candidate.
