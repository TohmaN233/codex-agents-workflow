# Main semantic handoff projection (2026-10-08)

`native_next` previously returned the canonical schema2 task index directly. Its `context_preparation.path` and `sha256` identify Host preparation diagnostics; the inline response also advertised the canonical index path. Those addresses were unnecessary for the Main's semantic task. The existing task text already contains admitted declared values, complete inline references and exact addresses for required materialized inputs/resources.

The Host now verifies the original canonical bytes against the unchanged dispatch receipt and verifies the retained preparation manifest against its nested digest and task digest. It projects only `schema_version` and the exact `task` for schema2. Inline delivery exposes this semantic value without a canonical or preparation path. Delivery uses the existing 12,000-byte inline boundary, applied to the projected bytes.

Larger packets use the existing Host Run artifact store outside the business workspace. The artifact name binds the exact attempt and semantic digest; the public path and its Host-derived SHA256 are returned together. Its exact canonical bytes must equal the projection derived from the original dispatch receipt, and the 16KiB index bound remains enforced. Reopening can materialize the exact missing public projection for an existing receipt; conflicting bytes or linked paths fail visibly. Publishing the public file never adds a new business-workspace effect or changes the original before-snapshot. Completion verifies the original canonical index, preparation metadata and any required public file before reserving a semantic turn or running a completion check. Models supply no integrity hashes.

The canonical task index, preparation metadata, sidecars and dispatch receipt are not rewritten. Historical schema1 Main receipts remain supported with their exact task plus the declared resource and verified-file addresses formerly stored beside it. Hashes, byte counts and preparation diagnostics stay Host-side. Semantic response schema, initiating Main identity, authority, lease/admission checks, snapshots, effect validation, automatic mechanical completion and original acceptance remain on the existing paths.

Independent review identified a path replacement race in the projection's initial file reads. The corrected projection reader checks ancestors and the initial regular-file identity, opens an owned descriptor, checks descriptor type/identity/size, reads at most the attested size plus one byte, then compares descriptor and retained path identities and checks links/ancestors again. Every opened descriptor receives a close attempt; read and close failures remain visible together. Exact digest and public-byte comparisons remain required. This reader is limited to canonical/preparation/public projection consumption; unrelated materializer reads are unchanged. Canonical and public indices retain 16KiB limits. Preparation metadata has a separate generous 64MiB ceiling matching the pinned Run resource-byte budget, so a legal manifest larger than the task index remains supported.

On POSIX, `O_NONBLOCK` and `O_NOFOLLOW` prevent a raced FIFO or final-component symlink from blocking or being followed at open. Windows Node does not provide equivalent open guarantees. Windows qualification establishes regular opened-descriptor reads and observed pre/post replacement/link/ancestor detection; it does not claim atomic no-reparse protection or nonblocking opening of a raced Windows named pipe. The actual POSIX FIFO and symlink race tests are explicitly skipped on this Windows host. Post-check validation cannot prevent changes after its final observation.

Verification uses the actual `WorkflowService.call('native_next', ...)` seam. The initial inline and file cases both failed because the model packet exposed `context_preparation`. Focused regressions cover both lanes, reopening unchanged canonical receipts, retention of exact declared sidecars, historical schema1 receipt addresses and rejection of canonical/preparation/public-file tampering before effects. The review race reproductions failed for all three packet paths before the descriptor repair. Further regressions cover missing/oversized/nonregular files, changed opened identities, actual identical-byte regular-file replacement, post-read link/ancestor swaps, growth/truncation and preserved read/close failures with every owned handle closed. Materializer tests retain their existing conflict and symlink checks. Exact logs, pre-change copies and file hash/diff evidence are retained outside the repository; the first reviewed candidate and its failures remain immutable, with corrected evidence in a separate revision. Repository qualification does not establish cohort speed, business quality or platform repair; installation and business execution evidence are recorded separately by the initiating Main.
